# Native connected-tool receiving adapter

Status: backend-facing engineering component. **No external receiver enrollment or positive Composio execution is qualified or activated.** No provider calls, new public admission route, credentials, account, installation, worker activation or dependency branch merge are part of this change.

The intended owner is the existing Relay native receiving host: `lib/v2/native-admission.ts::admitNativeCommand`. The host adapter must resolve the authenticated source Work mapping and existing native command transaction; it must not return request fields as its authority. The current Composio consumer remains closed until that host is enrolled and its adapter is implemented against real records and independently qualified. No verified authorized enrollment or real Work-to-Mission mapping was available in this checkout. Synthetic PostgreSQL fixtures demonstrate component transactions, not an authorized external integration.

## Canonical composition

`NativeReceivingHost` is trusted server configuration, never a request parameter. It supplies a pinned owner, organization, installation, backend, incarnation, enrollment version, audience, source verification key and Relay verification key. There is no provider-specific authority path or replacement policy registry. Policy wire bytes remain SHA-256 `4b198d32e1dcdc930c2658291906ebf72601e144596f3090202a3e7ee708d606`.

1. Authenticate the signed canonical workload credential and exact account/agent/runtime/task/workload audience.
2. Validate exact native Work/Mission/generation and connection/authority-version, descriptor, argument, target, capability and READ effect bindings. `resolveBinding(transaction, requested, parsedAction)` reads existing authorized native records and returns the actual server-resolved tool descriptor, including active connection lifecycle and owner/installation membership, and throws on unavailable or revoked records. The wrapper derives the actual argument hash, checks the descriptor hash and requires exact connection/target resource IDs. The host must validate arguments against that descriptor and execute that same descriptor, not accept hashes from the caller.
3. Verify the source permit's native action digest (`nativeAdmissionActionMaterial`, schema `relay.native-action.v1`). The action's source-permit hash is excluded from digest material to avoid a circular reference. Everything else is retained. Consumer-side resource hashing remains canonical Relay hashing (`sha256:`); admission wire hashing remains bare hexadecimal.
4. Under the existing account authority lock, verify signed durable source/Relay heads and exact equality with independently retained trusted heads. The witness must survive a receiver database rollback. Unavailable, rolled-back, wrong incarnation or unacknowledged policy fails closed. The host's mirror/witness enrollment must be qualified separately; a copied mirror in the same restored database is not an independent witness.
5. Invoke existing canonical policy/Passport/workload checks, approval consumption and budget reservation binding through `issueCapabilityLeaseInTransaction`; consume exactly one online call via `authorizeLeaseCallInTransaction`. No existing accounting, approval or authorization assertion is removed. Non-READ effects are rejected. This component qualifies only a `CONNECTOR_CALLS` reservation with zero monetary source authority; monetary dimensions or nonzero `budgetMicros` fail closed until a canonical price/currency mapping is separately qualified. Calls are never silently converted to monetary units. UNKNOWN applied budget state also denies new admission.
6. Commit the host's native command, audit and immutable `relay.native-admission.v1` receipt with the same transaction. The receipt uses existing `controlOutbox`; it is not a second execution ledger. The host callback may perform only database work and must implement its native idempotent command constraints. No provider effect is allowed before commit. A final same-transaction check revalidates the consumed approval, bound reservation and lease expiry after host work; expiry rolls the entire command and authority debit back.

Identical authenticated retries return the historical receipt without reissuing or consuming execution authority. Changed material conflicts. A receipt is evidence of prior admission, not a new dispatch grant. The existing native worker must independently fence/revoke writers and atomically claim its existing command. In particular, it must not interpret a historical receipt as permission to retry UNKNOWN effects.

## Controls, stop acknowledgments and recovery

`receiveNativeControl` verifies the original source-signed pause/revoke FENCE, exact enrollment and the current independently witnessed durable head (or a control retained by a later policy). It selects only the matching backend/incarnation/installation's commands admitted before that control version. Ordinary disable does not invoke this function or revoke admitted leases. Revoke fences even exhausted one-call leases; native writer fencing and provider resource inventory are supplied by the existing host's `applyControl` transaction callback.

`applyControl` must fence native writers or record qualified safe checkpoint suspension in its own canonical command records. It may enqueue a stop request, but it may report terminal resource states only from authenticated backend evidence persisted in that transaction. Missing resources or incomplete inventory produce `PENDING_BACKEND`; `STOP_UNKNOWN` and `STOP_FAILED` remain explicit. Every resource must identify an admitted command. The returned sidecar is the canonical `capability-control.lifecycle.v1` wire, copied byte-for-byte from MyEve, signed by the enrolled backend key. Delivery retries reuse identical receipts; changed evidence increments the sequence and preserves immutable per-sequence history.

No control acknowledgment releases budget reservations, converts UNKNOWN exposure, or claims a provider stopped merely because a request was queued. Native recovery must reconcile an ambiguous effect through authoritative provider evidence before allowing any retry. Restore must reconcile independently retained heads before admission resumes; a controller restart must never synthesize a new enrollment/incarnation to bypass a fence.

## Remaining integration requirements

- Authorized backend/key/environment enrollment and a durable independently retained witness.
- Existing authenticated source Work/Mission mapping; synthetic fixture Mission IDs cannot be installed as real mappings.
- Host adapter reading actual owner/connection/descriptor records under the account authority lock. All connection, descriptor, native mapping and policy writers must serialize with that same lock.
- Host adapter writing the existing native command and worker claim/fencing/status records, with authenticated provider reconciliation and complete resource inventory.
- Consumer adapter supplying exact native material and canonical remoteAdmission without loosening its current denial; frozen consumer source is unchanged by this pass.
- Canonical price/currency/reservation mapping before any monetary connected-tool authority; current component refuses monetary admission.
- Real enrolled receiver positive/negative, native worker concurrency/UNKNOWN/restart, resource-stop and composed browser qualification. Component fixture passes do not satisfy those external gates.
